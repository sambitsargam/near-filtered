# NEAR, Filtered

A pre-registered, reproducible test of one claim about NEAR — not a pitch
for it.

> **The claim we tested:** once you filter out bots and airdrop farming,
> NEAR's real economic usage is shifting toward cross-chain settlement
> through NEAR Intents — and that usage does, or does not, translate into
> value for NEAR token holders.

We wrote five hypotheses, the exact metric for each, and the result that
would count as **rejected**, and committed that file before pulling any
data. The git history is the proof. **Four of the five predictions went
against us, and this repository reports that.**

Every number in this thesis is generated from the data. `make verify`
checks it.

**Live dashboard: [near-filtered.vercel.app](https://near-filtered.vercel.app)**
— the same `results/metrics.json`, drawn as charts, served as static files
from `site/`.

## 1. Verdicts

Window **2025-11-01 to 2026-10-31**; dataset current to
2026-11-09 at the time of the run.

| # | Hypothesis | Verdict |
|---|---|---|
| H1 | Real usage — bot-filtered economic accounts | **REJECTED** — fell 69.6%, down in 23 of 27 sensitivity cells |
| H2 | Concentration | **REJECTED** — top-10 receiver share 14.8% → 62.2% |
| H3 | Retention | **INCONCLUSIVE** — the 95% interval spans zero |
| H4 | Cross-chain shift | **SUPPORTED** — share 1.73% → 10.73% |
| H5 | Value accrual | **REJECTED** — burn is 1.42% of issuance against a 10% bar |

## 2. Check our work in 2 minutes

1. `make install && make verify` — runs the unit tests, the number-drift
   check and a full rebuild from the committed aggregates. **No Google Cloud
   account, no API keys, no network.** It ends with the verdict per
   hypothesis, matching the table above.
2. Open [THESIS.md](THESIS.md) — regenerated by step 1 on your machine, so
   you are reading your own build of it.
3. Open the commit that added `HYPOTHESES.md` and compare its timestamp with
   the first commit touching `data/`. The hypotheses came first, and no
   hypothesis result existed anywhere until hours later.

## 3. The strongest evidence against this thesis

Deliberately near the top.

- **Real usage fell 69.6%** —
  from 50,158 to 15,267 economic
  accounts — and the decline is steeper at tighter thresholds, the opposite
  of a filter artefact.
- **Activity concentrated instead of broadening**: HHI rose from
  0.0047 to 0.0589.
- **Fee burn offsets 2.0% of net issuance** and is
  falling; no primary source documents any Intents fee reaching NEAR
  holders.
- **Our own bot filter leaks**: accounts clearing it averaged
  2,261
  transactions in 2025-11
  against a median of 36 —
  some are plainly automated. The conclusions survive because of the
  sensitivity grid, not the filter's precision.

## 4. The original metric: cross-chain settlement share

Of the economic activity NEAR settles in a month, what fraction settles
**across chains through NEAR Intents** rather than natively on NEAR?
Both legs are measured on the same sampled days; the headline form counts
transfers so it needs no token pricing at all.
It rose from 1.73% to
10.73% — but the
decomposition matters: Intents swaps grew
+11.6% while native
transfers fell -83.7%.
Part of the rise is a shrinking denominator, and the thesis says so in its
headline rather than a footnote.

Definition and caveats: [METHODOLOGY.md](METHODOLOGY.md) §6.

## 5. Data sources, cost and limits

| source | role |
|---|---|
| `bigquery-public-data.crypto_near_mainnet_us` | all on-chain series |
| NEAR Intents Explorer API | 1Click swaps — a **lower bound** on Intents activity |
| Primary docs, NEPs, governance posts | tokenomics parameters — [SOURCES.md](SOURCES.md) |

The full refresh behind the current results billed
**870.33 GiB** across 63 queries
(BigQuery's free tier is 1 TiB/month). Every query dry-runs first, carries a
hard byte cap, and appends to a committed cost ledger — so this paragraph is
itself generated.

Everything we know to be wrong or unmeasurable: [LIMITATIONS.md](LIMITATIONS.md).

## 6. Rerunning it live

`make refresh` re-pulls everything (needs `.env`; see `.env.example`), with
dry-run byte estimates printed before anything is spent. CI reruns
`make verify` on every push with no secrets, and a monthly workflow can
rerun the refresh with repository secrets (`GCP_SA_KEY`, `INTENTS_JWT`) —
see `.github/workflows/`.
